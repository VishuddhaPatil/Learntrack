# JVM Basics

## 1. What Is the JVM?

The Java Virtual Machine (JVM) is the runtime environment that executes Java bytecode. It allows compiled Java programs to run on different operating systems when a compatible Java runtime is available.

## 2. JDK, JRE, and JVM

- **JDK (Java Development Kit):** Provides tools for developing Java applications, including the Java compiler.
- **JRE (Java Runtime Environment):** A traditional term for the components needed to run Java applications, including the JVM and supporting libraries. Modern Java distributions may package these components differently.
- **JVM (Java Virtual Machine):** Executes Java bytecode.

## 3. How Java Code Executes

The basic execution process is:

1. Write source code in a `.java` file.
2. Compile it using `javac`.
3. The compiler generates `.class` files containing bytecode.
4. The JVM loads and executes the bytecode when the application runs.

For LearnTrack:

```bat
javac -d out -sourcepath src src\com\airtribe\learntrack\Main.java
java -cp out com.airtribe.learntrack.Main
```

The first command compiles the application. The second starts its main class.

## 4. Bytecode

Bytecode is the platform-independent instruction format generated by the Java compiler. The JVM interprets or compiles this bytecode into machine instructions for execution.

## 5. Class Loader

The class loader loads Java classes when they are needed. LearnTrack uses classes such as `Main`, `Student`, `Course`, and the service classes.

## 6. Memory Areas

Important JVM memory areas include:

- **Heap:** Stores objects and arrays.
- **Java stacks:** Hold method frames, local variables, and intermediate computations for each thread.
- **Method area:** Holds class-related runtime structures and metadata.
- **PC register:** Tracks the current JVM instruction for each thread.
- **Native method stacks:** Support native method execution.

## 7. Garbage Collection

Garbage collection automatically reclaims heap memory occupied by objects that are no longer reachable. Developers generally do not need to manually free ordinary Java objects.

## 8. Application Example

When LearnTrack creates a student using `new Student(...)`, a Student object is created at runtime. The service stores a reference to that object in a collection. As long as the object remains reachable, it can be accessed by the application.

## 9. Summary

Understanding compilation, bytecode, class loading, memory management, and garbage collection helps Java developers understand how applications are built and executed.
